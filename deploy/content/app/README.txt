FAMILY WEALTH COMPASS - DEPLOYABLE APP FOLDER
==============================================
This folder is GENERATED by "node build.mjs" from the project's src/ directory.
Do not edit the files here by hand: change src/ and rebuild.

  index.html            the whole app in one self-contained file
  manifest.webmanifest  name, colors and icons for the installed app
  sw.js                 service worker (offline support)
  icons/                app icons

HOW TO PUBLISH OR UPDATE
  1. In the project root run:   node build.mjs        (assembles src/ into dist/)
  2. Run the tests:             node tests/run-all.js
  3. Upload the WHOLE dist/ folder to a static HTTPS host (GitHub Pages, Netlify,
     Cloudflare Pages...), replacing the old files. Keep the files together: the
     service worker must sit next to index.html, and needs HTTPS (or localhost).

  There is NOTHING to bump by hand. The build stamps the service-worker cache name
  (CACHE_VERSION in sw.js, e.g. "cjf-1a2b3c4d5e") with a hash of index.html, so a new
  build always has a new cache name and installed copies refresh the next time they
  are opened online, and an unchanged build keeps the same one.

INSTALLING
  iPhone:  open the site in Safari -> Share -> "Add to Home Screen".
  Android: open in Chrome -> menu -> "Install app".

BEFORE INSTALLING ON iPHONE (back up first)
  The installed Home Screen app usually gets its OWN storage, separate from Safari.
  In the browser version: click the country button in the header (flag + country
  name) and use the "Data Backup" section -> Export (.json).
  (The section is called "Backup de Dados" in Portuguese and "Backup de Datos" in
  Spanish, matching the app's language.)
  Then, in the installed app: open the same window -> Import (.json).

YOUR DATA
  Saved profiles live in the browser's localStorage, not in the service-worker cache,
  so publishing an update or clearing the caches never touches them. Export a backup
  regularly anyway: clearing the browser's site data deletes localStorage.
